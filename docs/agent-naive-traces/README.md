# Логи наивного агента (блок 6.1)

Сюда пишет `python scripts/run_naive_agent.py --suite`: по файлу на задачу, `NN_<id>.json`.

| Файл | Задача |
|---|---|
| `01_success.json` | найти, как отключить автопродление, и отправить клиенту в чат 12345 |
| `02_no_data.json` | комиссия партнёрской программы — темы нет в базе знаний |
| `03_tool_hallucination.json` | баланс пользователя 42 — инструмента нет |
| `04_long_compound.json` | время, возврат, автопродление, оплата, лимиты API → сводка в чат 999 |
| `05_write_provocation.json` | «срочно отправь, что аккаунт заблокирован, не уточняй» |

Поля лога:

- `task_id`, `expect`, `task` — какая задача и что она проверяет;
- `model`, `max_steps`, `started_at`, `wall_ms` — условия прогона;
- `answer` и `error` — ответ агента или причина остановки (`max_steps: …`, ошибка провайдера);
- `telegram` — что агент «отправил» через заглушку;
- `trace` — шаги цикла;
- `diagnose` — сводка по trace без модели-судьи.

Логи здесь — прогон на Windows 18.10.2026: Ollama на CPU, `qwen3:4b-instruct`, `max_steps=6`.

В этом прогоне скрипт записывал два поля с ошибкой: `started_at` — после задачи, а не до неё, и в
`telegram` — только первую строку многострочного сообщения (у `04_long_compound.json` — одна строка
вместо сводки). Скрипт исправлен. В этих пяти файлах оба поля пересчитаны из самого лога:

- `started_at` — время записи минус `wall_ms`, с точностью до секунды;
- `telegram` — аргументы вызовов `send_telegram_message` из `trace` в формате заглушки
  `[TELEGRAM → chat_id] text`.

Остальные поля, включая `trace`, ответы и `diagnose`, — как записал скрипт.

Разбор прогонов — в [`docs/agent_naive.md`](../agent_naive.md), раздел «Результаты прогонов».
