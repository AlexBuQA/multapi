# Векторная база Qdrant (блок 5.2)

Эмбеддинги блока 5.1 (`bge-m3`, 1024 числа) лежат в Qdrant — коллекция `documents`, 110
фрагментов базы знаний с метаданными. Поиск — за миллисекунды и с фильтрами по метаданным.
На блоке 5.3 к этой же коллекции подключится LlamaIndex (`QdrantVectorStore`).

## Qdrant в compose

- **Образ `qdrant/qdrant:v1.19.1`** — точная версия, а не `latest`, и в паре с `qdrant-client` 1.19
  (`pyproject.toml`, `requirements.txt`): клиент и сервер должны совпадать по мажорной версии и
  расходиться по минорной не больше чем на 1. Расхождение `VectorStore` пишет в лог
  (`qdrant_version_mismatch`). 1.19.1 вышла 4 сентября 2026; 1.19.2 (5 октября) — слишком свежая.
- **Порты** `127.0.0.1:6333` (REST и дашборд http://localhost:6333/dashboard) и `127.0.0.1:6334`
  (gRPC) — только на этом компьютере, как Postgres.
- **Ключ API** `QDRANT__SERVICE__API_KEY: ${QDRANT_API_KEY:?…}` — из `.env`. Без ключа Qdrant
  пускает любого, поэтому без `QDRANT_API_KEY` `docker compose` не запускается вовсе и пишет, как
  ключ сгенерировать. Пустой ключ Qdrant считает «не задан» и отключает проверку — такую ошибку
  `:?` тоже ловит. Тот же ключ `app` получает из `.env` (`env_file`).
- **Том `qdrant_storage:/qdrant/storage`** — коллекции переживают `docker compose down` / `up` и
  пересоздание контейнера; удаляет их только `docker compose down -v`.
- **Проверка готовности по TCP**: `bash -c "exec 3<>/dev/tcp/127.0.0.1/6333"` — в образе нет curl и
  wget, а `/dev/tcp` — встроенная возможность bash (на нём же написан `entrypoint.sh` образа).
- `restart: unless-stopped`, телеметрия выключена (`QDRANT__TELEMETRY_DISABLED`).
- **`app` ждёт `qdrant: condition: service_healthy`** и получает `QDRANT_URL=http://qdrant:6333` —
  имя сервиса в сети compose. Для uvicorn и скриптов на хосте в `.env` — `http://localhost:6333`.

## Коллекция `documents`

- **Вектор** — один безымянный, размерность `EMBEDDING_DIM` (1024 у `bge-m3`), метрика
  **COSINE** (почему — «Метрика» ниже).
- **HNSW** — явно `HnswConfigDiff(m=16, ef_construct=100)`, это значения по умолчанию Qdrant.
  m — число связей у вершины графа, ef_construct — ширина поиска при построении. Для баз до
  сотен тысяч векторов это стандартный баланс точности, памяти и времени индексации; менять
  стоит, если замер recall на своих данных покажет потери. Пока векторов меньше порогов
  `full_scan_threshold` и `indexing_threshold` (10 000 КБ — около 2 500 векторов по 1024 числа),
  Qdrant графа не строит и ищет перебором, то есть точно: у нашей базы в 110 фрагментов (440 КБ)
  так и есть (`indexed_vectors_count: 0` в информации о коллекции), HNSW включится сам при росте
  базы.
- **Payload** каждой точки:

  | Поле | Индекс | Пример | Зачем |
  |---|---|---|---|
  | `source` | KEYWORD | `release_notes.md` | файл-источник; фильтр «только заметки о выпусках» |
  | `text` | — | «Новый тариф «Бизнес+»…» | сам фрагмент — уйдёт модели в RAG (блок 5.3) |
  | `created_at` | DATETIME | `2026-09-29T00:00:00Z` | дата редакции; фильтр «не старше 30 дней» |
  | `category` | KEYWORD | `billing` | **предметное поле** — раздел справки: account, billing, api, mobile, … |
  | `product` | KEYWORD | `mobile` | web, mobile, api, support |
  | `status` | KEYWORD | `actual` / `archived` | архивные редакции исключаются из выдачи |
  | `doc_id`, `title`, `chunk_index` | — | `RN-2026-09-29` | показать человеку, откуда ответ |

  Payload-индексы создаёт `ensure_collection` для полей, по которым идёт фильтрация: без индекса
  Qdrant проверяет условие перебором точек — на сотне это незаметно, на миллионе — нет.
- **Id точки** — `uuid5(NAMESPACE, "source#key")`, где key — id статьи (`KB-030`, `RN-2026-09-29`)
  или номер раздела. Одинаковый при каждом запуске: повторная загрузка перезаписывает те же
  точки. Номер раздела сдвигается, если в начало файла дописать раздел, поэтому у заметок и
  вопросов id задан явно, в комментарии под заголовком.

## Загрузка: `scripts/load_to_qdrant.py`

1. Фрагменты из `data/` → 2. `ensure_collection`: нет коллекции — создаётся с индексами; есть —
сверяется размерность и метрика (коллекция под другую модель — ошибка с подсказкой `--recreate`) →
3. векторы — `embed_documents` блока 5.1 (из его кеша: повторный запуск модель не вызывает), длина
каждого сверяется с `EMBEDDING_DIM` **до** записи → 4. `upsert` пачками по 128, `wait=True` на
последней: Qdrant применяет изменения по порядку, и после неё можно искать → 5. точки, которых
больше нет в `data/`, удаляются → 6. итог — `points_count` из `get_collection`.

Повторный запуск: «новых 0, перезаписано 110», `points_count` тот же — дублей нет.

Ошибки — понятным текстом, код выхода 2:
- модель вернула не ту длину: «Модель … возвращает векторы из 384 чисел, а EMBEDDING_DIM=1024 —
  размерность коллекции… Ничего не загружено»;
- коллекция под другую модель: «Коллекция documents создана для векторов из 1024 чисел, а
  EMBEDDING_DIM=384… пересоздайте коллекцию: python scripts/load_to_qdrant.py --recreate»;
- неверный ключ: «Qdrant не принял ключ (401): QDRANT_API_KEY в .env должен совпадать с ключом
  контейнера»; Qdrant не запущен: «Нет связи с Qdrant… docker compose up -d qdrant».

## `VectorStore` и сервис

- `app/services/vector_store.py` — единственное место, где есть `qdrant-client`: на блоке 5.3
  поиск переедет на LlamaIndex, а интерфейс `ensure_collection()`, `upsert(points, batch_size=256)`,
  `search(query_vector, top_k=5, query_filter=None) -> list[ScoredPoint]` останется.
- `search` — через `query_points` (старые методы `search` в Qdrant 1.19 устарели и убраны из
  спецификации REST API), с payload.
- **Один клиент на процесс.** В сервисе `VectorStore` создаёт lifespan (`app.state.vector_store`) и
  закрывает при остановке; эндпоинты получают его через `Depends(get_vector_store)`. Скрипты
  создают свой — один на запуск. `check_compatibility=False`: иначе клиент сверял бы версии
  синхронным запросом в фоновом потоке при создании; версию сверяет `ensure_collection`.
- **Lifespan** вызывает `ensure_collection`. Qdrant не отвечает — сервис всё равно стартует (чат от
  него не зависит, в лог — `vector_store_unavailable`); коллекция под другую модель — ошибка
  старта: работать с заведомо неверной конфигурацией хуже, чем упасть с понятным текстом.
- **`GET /kb/search?q=…&top_k=5&category=…&source=…&created_after=…&include_archived=false`** —
  вопрос → `embed_query` (в потоке: модуль эмбеддингов синхронный) → `search` с фильтром;
  архивные редакции исключены по умолчанию. Это проверка всей цепочки и в Docker, и основа RAG.
- Ключ по HTTP для локального адреса — норма (Qdrant на этом компьютере и в сети compose),
  поэтому предупреждение клиента «Api key is used with an insecure connection» для таких адресов
  скрыто; для внешнего адреса оно остаётся — там нужен https.

## Метрика

`python scripts/compare_metrics.py`: временные коллекции `documents_cosine` (COSINE) и
`documents_dot` (DOT) с одними и теми же векторами, пять вопросов пользователей, top-5 в каждой.
Векторы берутся от модуля эмбеддингов, а не из боевой коллекции: COSINE-коллекция нормирует
векторы при записи сама, и по ней не видно, нормирует ли их наш модуль. После опыта обе
временные коллекции удаляются — в проде одна коллекция.

Прогон на Windows с `bge-m3` (10.10.2026): длина векторов модуля — от 1.000000 до 1.000000.

| Вопрос | top-5 cosine | top-5 dot | Совпало |
|---|---|---|---|
| Как сменить пароль? | KB-019, RN-2026-02-10, KB-001, ARC-PASSWORD-2025, KB-004 | KB-019, RN-2026-02-10, KB-001, ARC-PASSWORD-2025, KB-004 | да |
| Письмо для подтверждения не пришло, что делать? | KB-006, FAQ-07, FAQ-10, REG-2, KB-001 | KB-006, FAQ-07, FAQ-10, REG-2, KB-001 | да |
| API возвращает ошибку 429. Что это значит? | KB-009, KB-037, KB-038, ARC-API-V1-LIMITS, KB-035 | KB-009, KB-037, KB-038, ARC-API-V1-LIMITS, KB-035 | да |
| Можно ли вернуть деньги за тариф? | ARC-REFUND-2025, RN-2026-05-19, KB-027, KB-030, KB-029 | ARC-REFUND-2025, RN-2026-05-19, KB-027, KB-030, KB-029 | да |
| Как включить вход по отпечатку пальца в приложении? | KB-041, RN-2026-09-15, KB-010, FAQ-08, RN-2025-04-08 | KB-041, RN-2026-09-15, KB-010, FAQ-08, RN-2025-04-08 | да |

Близость первого результата в обеих коллекциях одна и та же до четвёртого знака: 0.7724,
0.7061, 0.6306, 0.7237, 0.7566. Ранжирование совпало на всех пяти вопросах — sanity check
пройден. Контрольный опыт (векторы домножены на 0,5–2,0): у косинуса ранжирование то же на 5 из
5 вопросов, у скалярного произведения — на 0 из 5.

Попутная находка: на «Можно ли вернуть деньги за тариф?» первым идёт **архивная** редакция
ARC-REFUND-2025 («7 дней») — выше действующих RN-2026-05-19 и KB-030 («14 дней»). Без фильтра
по `status` RAG ответил бы устаревшими условиями; поэтому `GET /kb/search` исключает архивные
редакции по умолчанию (пример 3 в «Фильтрах»).

**Почему COSINE.** Модуль эмбеддингов нормирует векторы (длина 1), а для таких векторов косинус
и скалярное произведение — одно и то же число: ранжирование COSINE и DOT совпадает, это и есть
sanity check. Скорость тоже одинаковая: COSINE в Qdrant — это DOT по векторам, нормированным при
записи. Разница в том, что будет при ошибке. Контрольный опыт скрипта: те же векторы, умноженные
на разные числа 0,5–2,0 (так выглядели бы ненормированные), — у косинуса ранжирование не
меняется, у скалярного произведения меняется (на всех пяти вопросах): длинные
векторы выигрывают независимо от смысла. Сменим провайдера эмбеддингов, который не нормирует
ответ, — COSINE это переживёт, DOT молча испортит поиск. Поэтому в production — COSINE; DOT
имел бы смысл, только если бы нормирование было гарантировано и важна была бы каждая доля
процента CPU на записи.

## Фильтры

`python scripts/qdrant_filters_demo.py --today 2026-10-10` — для каждого примера вопрос, код
фильтра и top-3 без фильтра и с ним.

1. **Match по строке** — только заметки о выпусках:
   ```python
   Filter(must=[FieldCondition(key="source", match=MatchValue(value="release_notes.md"))])
   ```
2. **Range по дате** — редакции не старше 30 дней:
   ```python
   since = (datetime.now(UTC) - timedelta(days=30)).strftime("%Y-%m-%dT%H:%M:%SZ")
   Filter(must=[FieldCondition(key="created_at", range=DatetimeRange(gte=since))])
   ```
3. **must + must_not** — раздел billing без архивных редакций (аналог «только тенант X, исключая
   архивные документы»: самый частый фильтр в production-RAG):
   ```python
   Filter(
       must=[FieldCondition(key="category", match=MatchValue(value="billing"))],
       must_not=[FieldCondition(key="status", match=MatchValue(value="archived"))],
   )
   ```

## pgvector (опционально) — не делали

В compose уже есть Postgres, но образ `postgres:16-alpine` без расширения pgvector: для опыта
пришлось бы сменить образ на `pgvector/pgvector` и завести вторую копию данных. Для базы в 110
фрагментов и одного сервиса оба варианта работают за миллисекунды; Qdrant выбран как основной
заранее — ради payload-индексов, фильтров без SQL и будущего гибридного поиска (sparse-векторы)
в RAG блока 5.3.
