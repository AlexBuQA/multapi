# API личного кабинета

Ключи, лимиты, версии, вебхуки и тестовая среда API.

## Создание и отзыв API-ключа

Откройте раздел «API-ключи» и нажмите «Создать ключ», задайте имя и права доступа. Ключ показывается один раз — сохраните его сразу. Скомпрометированный ключ отзовите кнопкой «Отозвать» и создайте новый.

## Где получить API-ключ?

API-ключ создаётся в «API» → «Ключи» → «Создать ключ»: задайте название и права доступа. Ключ показывается один раз — сохраните его в надёжном месте. Утерянный ключ восстановить нельзя, только отозвать и создать новый.

## Права доступа API-ключа

При создании ключа выберите права: «Только чтение» или «Чтение и запись». Ключ с правами чтения не может создавать и изменять данные — такие запросы вернут код 403. Права существующего ключа изменить нельзя: создайте новый ключ.

## Ограничение API-ключа по IP-адресам

В настройках API-ключа можно указать список разрешённых IP-адресов. Запросы с других адресов отклоняются с кодом 403. Пустой список означает, что ограничений нет.

## Ограничение API-ключа по IP-адресам

Для API-ключа можно задать список разрешённых IP-адресов и подсетей: запросы с других адресов получат ошибку 403. Настройка — в «API» → «Ключи» → «Ограничения». Рекомендуем включить её для ключей интеграций, работающих с сервера.

## Лимиты API и ошибка 429

Лимит запросов к API зависит от тарифа. При превышении API возвращает код 429 и заголовок Retry-After — повторите запрос после указанного времени. Чтобы повысить лимит, перейдите на тариф выше в разделе «Биллинг» → «Тариф».

## Сколько запросов в минуту можно делать к API?

Лимит зависит от тарифа: «Старт» — 60 запросов в минуту, «Команда» — 300, «Бизнес» — 1 200. При превышении API отвечает кодом 429 и заголовком Retry-After. Текущий расход лимита видно в «API» → «Статистика».

## Версии API

Текущая версия API — v2, адрес https://api.example.com/v2. Версия v1 поддерживается до 31 декабря 2026 года, после этого запросы к ней вернут код 410. Изменения перечислены в разделе «API» → «История изменений».

## API v2

Вышла версия API v2: единый формат ошибок, постраничная выдача и права доступа на уровне ключа («Только чтение», «Чтение и запись»). Адрес — https://api.example.com/v2. Версия v1 продолжает работать, но новых возможностей в ней не будет.

## API v1 отключается 31 декабря 2026 года

Напоминаем: 31 декабря 2026 года API v1 будет отключён, запросы к нему начнут возвращать код 410. Переведите интеграции на v2 — список отличий в «API» → «История изменений». Заодно в вебхуках появились события об изменении тарифа и об оплате по счёту.

## Ошибка 401 при запросе к API

Код 401 означает, что ключ не передан, указан с ошибкой или отозван. Передавайте ключ в заголовке Authorization: Bearer <ключ>. Проверьте в разделе «API-ключи», что ключ активен.

## Вебхуки

настраиваются в «API-ключи» → «Вебхуки»: укажите URL и выберите события. Сервис отправляет POST-запрос с JSON и подписью в заголовке X-Signature. Если ваш сервер не ответил кодом 200, доставка повторяется 5 раз с растущей паузой.

## Подпись вебхуков

Запросы вебхуков теперь подписываются: в заголовке X-Signature передаётся HMAC-SHA256 тела запроса с секретом вебхука. Проверяйте подпись на своей стороне, чтобы отличать наши запросы от поддельных. Секрет показывается один раз при создании вебхука.

## Тестовая среда API

Для отладки интеграции используйте тестовую среду https://sandbox.example.com/v2. Ключи для неё создаются отдельно, данные не влияют на рабочий аккаунт и очищаются раз в неделю. Лимиты запросов в тестовой среде ниже, чем на тарифе.

## Чем тестовая среда API отличается от рабочей?

Тестовая среда (sandbox.api.example.com) принимает те же запросы, но данные в ней не настоящие и оплата не списывается. Ключи тестовой среды не работают в рабочей, и наоборот. Данные тестовой среды очищаются раз в неделю.
